# 0.1.23 — smaller-disk exports and useful preparation progress

Long FLAC exports can run with sequential disk checks when the full upfront estimate exceeds available capacity. This path runs one export at a time, reserves space for two uncompressed 24-bit stereo output/scratch tracks, checks each audio-tool step, and checks the actual ZIP payload before packaging. It supports original recording exports with raw originals, mixes, intros, normalization, and silence trimming. Edited-source exports, transcription, and uploads retain their existing full upfront reservation. The recording reserve and emergency disk monitor remain active. Failed steps remove temporary output and preserve source recordings.

Corrected Opus intermediates are removed after each speaker. Unchanged raw and processed FLAC initially share hard links; later processing writes replacements, preserving the originals. Silence detection skips already-active windows without changing shared cut positions or its 100 ms detection grid.

Preparation status identifies the speaker and operation, reports processed audio time during encoding and analysis, and gives a current-pass ETA based on observed speed after a brief warm-up. The ETA resets between passes; it is not an overall completion promise. Recording identity is shown in the Discord link reply and job page.

Audacity imports speaker-named media automatically using the Craig-style .aup workflow. ZIP names include the UTC recording start date, server and room, with saved IDs as fallbacks for older metadata. Individual processed download names identify the speaker. Intro matching keeps the project intro matched to the voices while applying any separate mix adjustment inside the mix, rather than changing the project's intro file.

Validation before release: 253 passing tests, three optional tests skipped. Tests cover constrained-space execution, exclusive admission, disk-step failure cleanup, raw source preservation, ZIP sizing, progress, ETA calculations, cross-session routing, shared-cut synchronization, and separate project/mix intro levels. A full October 27 recording resource benchmark is also running locally with a one-GiB/no-swap memory cap and a two-core quota; its complete peak usage remains unverified at release preparation time. The VPS export must be cancelled through its normal job endpoint before deployment; recordings must remain idle for the existing deployment guard.
