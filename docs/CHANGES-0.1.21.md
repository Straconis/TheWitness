# 0.1.21 — configurable recording-start sound

An original short chime now plays once after each new recording becomes active, including manual, automatic, scheduled and event starts. Existing servers default to the chime. Reconnects, repeated starts of an existing session and stopping do not replay it. Playback runs independently of capture; missing Speak permission, unavailable audio, synchronous playback errors or connection playback errors leave recording active. Delayed playback is skipped if its recording has already stopped.

`/startsound mode:status|default|custom|off` controls each server. Changes require Manage Server and any configured Wrangler role; status remains open. Off reminds the manager that participants rely on the recording panel notice. The manager dashboard supports uploading, previewing and selecting custom sounds; old/read-only dashboard links cannot modify the sound or access its preview.

Uploads accept WAV, FLAC, MP3 or Ogg up to 5 MiB. Conversion is bounded to 60 seconds, with one start-sound conversion at a time, forced demuxing, a file/pipe protocol whitelist and spare-disk check. Converted sounds must be 0.2–10 seconds, targeting -20 LUFS / -3 dBTP, 48 kHz stereo Opus at 96 kb/s with 20 ms frames. IDs are server-assigned and uploaded snapshots are immutable. Uploading saves a custom choice without changing the current mode; select Custom to enable it. Abandoned uploads expire after one hour and unreferenced sounds after 48 hours; saved custom IDs are retained even in Default or Off mode.

`START_SOUND=on|off` defaults to on; off disables every server’s sound. `START_SOUND_DEFAULT_PATH` optionally replaces the bundled chime. The override is validated at startup as a regular Ogg Opus file <=1 MiB, 0.2–10 seconds, stereo with 20 ms frames and valid decodable packets. Invalid overrides fall back to the bundled asset. Missing/unreadable custom sounds fall back to the default; a missing default skips. Default playback does not run FFmpeg. The release package includes assets/ and the original synthesized chime’s provenance, checksum and generator.

Capture explicitly excludes the bot’s own user ID. Discord does not return outgoing audio to the bot’s receiver, but participant microphones can still capture acoustic echo. The audible notice does not replace consent or the recording panel. README, help, environment examples and hosted policies document the behavior; policy effective date is October 7, 2026. Help also corrects the server-intro uploader location to the manager dashboard, and the privacy retention text now reflects the artifact cleanup introduced in 0.1.20.

Validation: 187/187 local tests, including all four real start entry paths with fake voice connections, repeat/reconnect/stop suppression, permissions, playback-error isolation, fallbacks, packet decoding, uploads, manager capability protection, preview and retention. The shipped asset SHA-256 matches the supplied checksum and Eris parses all 68 packets. Live DAVE playback and microphone echo remain unverified; deployment is explicit and manual. No root admin tools changed.
